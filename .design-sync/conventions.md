## How to build with this system

**No root provider.** Components work as-is. Three exceptions: `Toaster` must be mounted once for `toast()` calls (from `sonner`) to show; `Tooltip` sits inside a `TooltipProvider`; the `Sidebar*` parts sit inside `SidebarProvider`. Charts: draw with `Recharts` from the bundle (`const { AreaChart, Area } = window.EdgecomDS.Recharts`) inside `ChartContainer` — a separate recharts copy renders nothing, and chart text inherits the scale from it: never set `fontSize` on a Recharts element. Dark mode is a `class="dark"` on any ancestor — every token flips; never hand-pick dark colours.

**Styling idiom: Tailwind utilities that name semantic tokens.** The stylesheet you get (`styles.css` → `_ds_bundle.css`) is compiled and fixed: a utility class that is not in it does nothing, silently. Use the families below (all present), and for anything else inline the token: `style={{ background: "var(--elevated)" }}`. Never a hex, never a px font size.

| Need | Use |
|---|---|
| Surfaces | `bg-background` `bg-card` `bg-popover` `bg-elevated` `bg-muted` `bg-secondary` `bg-sidebar` |
| Text | `text-foreground` `text-muted-foreground` `text-card-foreground` `text-primary` `text-primary-foreground` |
| Status (by meaning only) | `bg-success` `bg-warning` `bg-info` `bg-destructive` and `-subtle` tints (`bg-success-subtle` …), text `text-success` `text-warning` `text-info` `text-destructive`, emphasis `text-destructive-emphasis` |
| Borders / focus | `border-border` `border-input` `border-primary` `ring-ring/50` `ring-foreground/10` |
| Type scale (only these) | `text-caption` `text-body-sm` `text-body` `text-body-lg` `text-title` `text-heading` `text-display` — each carries its own line-height and weight; never pair with `leading-*`; never `text-sm`/`text-xs`. Emphasis inside body text is `font-medium` (`text-body-sm font-medium`), never an inline `font-weight` |
| Radius | `rounded-sm` (badges) `rounded-md` (buttons, inputs) `rounded-lg` `rounded-xl` (cards) `rounded-full` |
| Layout | `flex` `grid` `grid-cols-1` `grid-cols-2` `grid-cols-3` `gap-2` `gap-3` `gap-4` `p-4` `p-6` `px-3` `py-2` `w-full` `min-w-0` `truncate` `tabular-nums` — responsive at `sm:` and `md:`: `sm:grid-cols-2` `sm:grid-cols-3` `md:grid-cols-3` `sm:flex-row` `hidden md:flex` `md:hidden`, so a phone stacks what a desktop puts side by side. A grid written as an inline `grid-template-columns` cannot respond — write the classes. Scrolling inside a card: a horizontal rail of tiles is `scroll-rail` (mount `ScrollRail`, below), a vertical pane beside another is `scroll-pane` — both carry the pill scrollbar (`scrollbar-pill`, for any other scrollport in a card), never the OS one. Chart heights, the only ones compiled: `h-[240px]` `h-[260px]` `h-[280px]` `h-[320px]` `h-[360px]` `h-[380px]` `h-[400px]` `h-[420px]` `h-[560px]` |
| Commodities (tags only) | `<Badge variant="electricity">` — likewise `water` `gas` `temperature` `emissions`. Never hand-compose a commodity tag from chart classes. Chart series labels may use `text-chart-<commodity>-700`. |

Rules that the audit found broken most often: a quiet delete in a table row is `<Button variant="ghost-destructive">`, never `ghost` plus red classes. Every destructive action goes through `AlertDialog`. `Select` shows no checkmark on the chosen option. `DropdownMenu` shrink-wraps to its widest item. `Dialog` is for 1–4 fields; longer forms go to `Sheet`. Neutral labels are `<Badge variant="outline">`.

**Looks like markup, is a component.** These read like plain HTML and are mounted all the same, because the system styles them and a hand-drawn copy drifts: `Alert` (any tinted callout with an icon and a title — never a `bg-*-subtle` box), `Separator`, `Label`, `Tooltip`, `Switch` with its `Label`, `Badge`, `Breadcrumb` and its parts, `Table` and its parts, `Skeleton`, `Progress`, `RadialGauge`, and a horizontal rail of tiles — `ScrollRail` with a `ScrollRailItem` per `Card size="sm"` tile, which carries the `scroll-rail` scrollbar and the 2px bleed that keeps the tiles' ring whole; never a `flex overflow-x-auto` div with a hand-written bleed. Text on a tint is the tone's `-emphasis` token.

**A table in a card is one recipe.** `CardContent` with `class-name="px-0"`; `TableHeader variant="strong"`; every head and cell in the first and last column `first:pl-(--card-spacing) last:pr-(--card-spacing)`; numbers `text-right tabular-nums`; a date that opens the day is `Button variant="link" class-name="h-auto p-0"`; a footnote marker is a `Tooltip` on a `*`. Alignment goes in `class-name` on the head or cell — a `style` attribute on an `x-import` never reaches the cell.

**The chart header is one composition.** `CardHeader` > `CardTitle` + a last-updated `CardDescription`; `CardAction` > [primary action `Button`] [`Toggle variant="outline"` — the two-state overlay or horizon switch, never a Button swapping variants] [`ToggleGroup variant="outline" layout="connected"` — the range presets, one strip, the outline default] [compact `DatePicker`] [export `DropdownMenu` icon button], every control at `size="default"`. Then the axis caption as `text-caption` above the plot, the time-zone line under it, the legend centred, the threshold strip last. An app may draw its plots with another library (Highcharts, say) and a canvas draws with the bundle's Recharts; both read the chart theme tokens (`chart-grid`, `chart-axis-label`, `chart-reference`, `chart-series-width`, `chart-reference-width`) and the legacy line and window variables a ported plot cites (`--chart-legacy-line-<colour>`, `--chart-legacy-peak-1..7`, `--chart-legacy-window-high|normal|low`), all of which the stylesheet carries. A figure against its ceiling is `RadialGauge` (`size` `card` or `tile`), toned by its text colour only when judged against a target.

**An app page is the shell's child.** `ApplicationShell` is bound to the viewport, its top bar stays and its content area is the one scrollport; the page's breadcrumb goes in the shell's `heading` prop, after the rail toggle, and the page starts at its H1. The content area already pads the page: a page adds no padding and no max-width.

**Every design ships a manifest.** Beside each `<Name>.dc.html` write `<Name>.manifest.json`, starting from `_manifest.example.json` in this project or, where that file is not beside you, from https://design.edgecom.ai/design-manifest.example.json — both are stamped with the system's current `designSystemVersion` and `designSystemDigest`, which are copied, never typed. One `components` entry per design-system element — and a component inside another is its own entry: a `Field` inside a `Sheet` is a `field` instance, not a part of `sheet`. Each entry carries a kebab-case `instanceId`, written literally on that design-system element as `data-instance` — never on a layout `<div>`, never as a template expression; an element the logic builds, such as a chart made with `React.createElement`, takes it in its props (`{ "data-instance": "reading-chart" }`); a loop that renders several of one component declares one instance and stamps that one id on every item — the registry `component` id such as `alert-dialog`, its `variants` by axis — the axes its spec lists; an axis the data drives lists every option it takes, as an array (`"variant": ["destructive", "warning", "info"]`); `variant` and `size` are axes on every component that offers them; `orientation` is one only where the spec lists it (`Field`, `ButtonGroup` — on `Stepper` or `Tabs` it is a prop), and `side`, `collapsible`, `compact` and other props are not variants and are not recorded — a component whose spec lists no variants takes no `variants` — and its `parts`. An instance's `states` are the screen states it takes part in (`loading`, `empty`, `error`, `success`, `disabled`), never a control's own state such as checked. `tokens` lists the token ids reached for directly; scale steps (radius and type steps) are utilities, not tokens. `viewports`, `themes` and `states` name what is covered — `mobile` + `desktop`, `light` + `dark`, `loading` + `empty` + `error` + `success` are all required. An `approvedExceptions` entry names who has approved it; "pending" is a deviation to report. The schema is https://design.edgecom.ai/schemas/design-manifest.schema.json and the validator https://design.edgecom.ai/tools/check-design-manifest.mjs; the implementing agent runs it (`node check-design-manifest.mjs <Name>.manifest.json --design <Name>.dc.html`) and reads the manifest before the design, so every line it would print is a defect to fix here — and for a canvas design a missing viewport, theme or state is an error, not a warning.

**Presenting a design.** A portal page renders inside `ApplicationShell` — pass `nav`, `activeItem`, `user` and `buildings`, and the page as its children; never hand-build a sidebar and top bar from `Sidebar*` parts. One screen per design file. The design is responsive: the phone layout is the same file at a phone width (set the preview width to 390 to check it), never a phone frame drawn beside the desktop on one canvas. The screen's state and theme are the Design Component's props (`data-props`: `state` as `live | loading | empty | error`, `theme` as `light | dark`), switched from the props panel — never an on-canvas harness bar above the page. Every control in one toolbar takes the same `size`. Icons are lucide: inline the icon's 24×24 path at `size-4` with `stroke="currentColor"` and name it on the element as `data-lucide="bell-ring"`, so the implementer installs the same icon from `lucide-react`.

**Where the truth lives.** This README is the whole instruction a project receives with the design system; everything else is a file beside it or an address. `styles.css` → `_ds_bundle.css`: the first block is every token (`:root` light, `.dark` overrides) in OKLCH; the same list with every value is https://design.edgecom.ai/tokens.json. The full design language and usage rules — read them before a screen — are `guidelines/design.md` where that folder is beside you, and https://design.edgecom.ai/design.md where it is not. Per component: `components/general/<Name>/<Name>.prompt.md` (variants, sizes, parts, rules) and `<Name>.d.ts` (the props you may pass) in the design system, or the published contract at `https://design.edgecom.ai/contracts/<id>.json` — the index is https://design.edgecom.ai/contracts/index.json.
