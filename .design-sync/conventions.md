## How to build with this system

**Loading it on a canvas.** Install the system by copying four files into the canvas at the same paths under `project/ds/<folder>/`: `components/bundle.css`, `components/bundle.js`, `_system.json` and `_manifest.example.json`. Each artboard links the stylesheet, then the script, right after its `support.js` line (`<link rel="stylesheet" href="ds/<folder>/components/bundle.css">`, `<script src="ds/<folder>/components/bundle.js"></script>`). The canvas supplies React; the bundle carries none. `components/bundle.js` defines `window.EdgecomDS`. Mount a component with `<x-import component-from-global-scope="EdgecomDS.Button" variant="outline" size="sm">Open site</x-import>`. Props are attributes, written kebab-case (`default-value`, `active-item`), with `{{ }}` holes for booleans, numbers, arrays, objects and handlers. Extra classes on a component go in `class-name`, which merges with the component's own. Element content is `children`; a nested `x-import` is a child component. Screens, layout and copy stay markup; every control the system has is mounted, never redrawn.

**No root provider.** Components work as-is. Three exceptions: `Toaster` must be mounted once for `toast()` calls (from `sonner`) to show; `Tooltip` sits inside a `TooltipProvider`; the `Sidebar*` parts sit inside `SidebarProvider`. Charts: draw with `Recharts` from the bundle (`const { AreaChart, Area } = window.EdgecomDS.Recharts`) inside `ChartContainer` — a separate recharts copy renders nothing, and chart text inherits the scale from it: never set `fontSize` on a Recharts element. Dark mode is a `class="dark"` on any ancestor — every token flips; never hand-pick dark colours.

**Styling idiom: Tailwind utilities that name semantic tokens.** The stylesheet you get (`components/bundle.css`) is compiled and fixed: a utility class that is not in it does nothing, silently. Use the families below (all present), and for anything else inline the token: `style={{ background: "var(--elevated)" }}`. Never a hex, never a px font size.

| Need | Use |
|---|---|
| Surfaces | `bg-background` `bg-card` `bg-popover` `bg-elevated` `bg-muted` `bg-secondary` `bg-sidebar` |
| Text | `text-foreground` `text-muted-foreground` `text-card-foreground` `text-primary` `text-primary-foreground` |
| Status (by meaning only) | `bg-success` `bg-warning` `bg-info` `bg-destructive` and `-subtle` tints (`bg-success-subtle` …), text `text-success` `text-warning` `text-info` `text-destructive`, emphasis `text-destructive-emphasis` |
| Borders / focus | `border-border` `border-input` `border-primary` `ring-ring/50` `ring-foreground/10` |
| Type scale (only these) | `text-caption` `text-body-sm` `text-body` `text-body-lg` `text-title` `text-heading` `text-display` — each carries its own line-height and weight; never pair with `leading-*`; never `text-sm`/`text-xs`. Emphasis inside body text is `font-medium` (`text-body-sm font-medium`), never an inline `font-weight` |
| Radius | `rounded-sm` (badges) `rounded-md` (buttons, inputs) `rounded-lg` `rounded-xl` (cards) `rounded-full` |
| Layout | `flex` `grid` `grid-cols-1` `grid-cols-2` `grid-cols-3` `gap-2` `gap-3` `gap-4` `p-4` `p-6` `px-3` `py-2` `w-full` `min-w-0` `truncate` `tabular-nums` — responsive at `sm:` and `md:`: `sm:grid-cols-2` `sm:grid-cols-3` `md:grid-cols-3` `sm:flex-row` `hidden md:flex` `md:hidden`, so a phone stacks what a desktop puts side by side. A grid written as an inline `grid-template-columns` cannot respond — write the classes |
| Commodities (tags only) | `<Badge variant="electricity">` — likewise `water` `gas` `temperature` `emissions`. Never hand-compose a commodity tag from chart classes. Chart series labels may use `text-chart-<commodity>-700`. |

Rules that the audit found broken most often: a quiet delete in a table row is `<Button variant="ghost-destructive">`, never `ghost` plus red classes. Every destructive action goes through `AlertDialog`. `Select` shows no checkmark on the chosen option. `DropdownMenu` shrink-wraps to its widest item. `Dialog` is for 1–4 fields; longer forms go to `Sheet`. Neutral labels are `<Badge variant="outline">`.

**Every design ships a manifest.** Beside each `<Name>.dc.html` write `<Name>.manifest.json`, starting from the `_manifest.example.json` you installed with the system. Copy `designSystemVersion` and `designSystemDigest` from the installed `_system.json`, never type them. That copy names the version the canvas was drawn against, even after the system moves on. Only where no copy is installed, start from https://design.edgecom.ai/design-manifest.example.json. One `components` entry per design-system element — and a component inside another is its own entry: a `Field` inside a `Sheet` is a `field` instance, not a part of `sheet`. Each entry carries a kebab-case `instanceId`, written literally on that design-system element as `data-instance` — never on a layout `<div>`, never as a template expression; an element the logic builds, such as a chart made with `React.createElement`, takes it in its props (`{ "data-instance": "reading-chart" }`); a loop that renders several of one component declares one instance and stamps that one id on every item — the registry `component` id such as `alert-dialog`, its `variants` by axis — the axes its spec lists; an axis the data drives lists every option it takes, as an array (`"variant": ["destructive", "warning", "info"]`); `variant` and `size` are axes on every component that offers them; `orientation` is one only where the spec lists it (`Field`, `ButtonGroup` — on `Stepper` or `Tabs` it is a prop), and `side`, `collapsible`, `compact` and other props are not variants and are not recorded — a component whose spec lists no variants takes no `variants` — and its `parts`. An instance's `states` are the screen states it takes part in (`loading`, `empty`, `error`, `success`, `disabled`), never a control's own state such as checked. `tokens` lists the token ids reached for directly; scale steps (radius and type steps) are utilities, not tokens. `viewports`, `themes` and `states` name what is covered — `mobile` + `desktop`, `light` + `dark`, `loading` + `empty` + `error` + `success` are all required. An `approvedExceptions` entry names who has approved it; "pending" is a deviation to report. The schema is https://design.edgecom.ai/schemas/design-manifest.schema.json and the validator https://design.edgecom.ai/tools/check-design-manifest.mjs; the implementing agent runs it and reads the manifest before the design, so every line it would print is a defect to fix here.

**Presenting a design.** A portal page renders inside `ApplicationShell` — pass `nav`, `activeItem`, `user` and `buildings`, and the page as its children; never hand-build a sidebar and top bar from `Sidebar*` parts. One screen per design file. The design is responsive: the phone layout is the same file at a phone width (set the preview width to 390 to check it), never a phone frame drawn beside the desktop on one canvas. The screen's state and theme are the Design Component's props (`data-props`: `state` as `live | loading | empty | error`, `theme` as `light | dark`), switched from the props panel — never an on-canvas harness bar above the page. Every control in one toolbar takes the same `size`. Icons are lucide: inline the icon's 24×24 path at `size-4` with `stroke="currentColor"` and name it on the element as `data-lucide="bell-ring"`, so the implementer installs the same icon from `lucide-react`.

**Where the truth lives.** This README is the whole instruction a canvas receives with the design system; everything else is a file of the system or an address. `tokens.json` holds every colour in light and dark, the type scale and the radii. `components/bundle.css` opens with the same tokens as CSS (`:root` light, `.dark` overrides) in OKLCH, and https://design.edgecom.ai/tokens.json publishes them too. The full design language and usage rules are `guidelines/design.md`, also at https://design.edgecom.ai/design.md; read them before a screen. Per component: `components/<Name>/README.md` (variants, sizes, parts, rules), `<Name>Props` in `components/index.d.ts` (the props you may pass), or the published contract at `https://design.edgecom.ai/contracts/<id>.json` (index: https://design.edgecom.ai/contracts/index.json).

```html
<x-import component-from-global-scope="EdgecomDS.Card" class-name="w-full max-w-sm" data-instance="site-card">
  <x-import component-from-global-scope="EdgecomDS.CardHeader">
    <x-import component-from-global-scope="EdgecomDS.CardTitle">Northridge Distribution Center</x-import>
    <x-import component-from-global-scope="EdgecomDS.CardDescription">14 meters · live load 1.24 MW</x-import>
  </x-import>
  <x-import component-from-global-scope="EdgecomDS.CardContent" class-name="flex items-center justify-between gap-3">
    <x-import component-from-global-scope="EdgecomDS.Badge" variant="outline" data-instance="commodity-tag">Electricity</x-import>
    <span class="text-body-sm text-muted-foreground tabular-nums">Peak 412 kW</span>
    <x-import component-from-global-scope="EdgecomDS.Button" size="sm" variant="outline" data-instance="open-site">Open site</x-import>
  </x-import>
</x-import>
```
